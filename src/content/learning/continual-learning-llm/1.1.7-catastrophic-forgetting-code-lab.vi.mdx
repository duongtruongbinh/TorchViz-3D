## Tổng quan Bài lab & Phương pháp Đánh giá

Lab này trả lời một câu hỏi đơn giản: sau khi model học Task B, nó còn làm được Task A không?

Ta cho DistilGPT-2 học Task A trước, rồi tiếp tục fine-tune cùng model đó trên Task B. Trong lúc học B, model không được xem lại dữ liệu A.

Sau mỗi giai đoạn, ta kiểm tra cả hai task bằng các câu **held-out** — những câu không nằm trong tập train. Nhờ vậy, ta đo được model còn thực hiện task cũ tốt đến đâu, thay vì chỉ kiểm tra nó nhớ các câu đã thấy.

<LessonNote tone="fact">
  Nếu accuracy B tăng còn accuracy A giảm sau khi fine-tune B, model đã học điều mới nhưng quên một phần năng lực cũ. Đó là Catastrophic Forgetting.
</LessonNote>

</MdxPage>

## Bối cảnh: hai năng lực ngôn ngữ học nối tiếp

**Task A — Sentiment.** Model đọc một nhận xét ngắn và trả về `positive` hoặc `negative`.

```text
Instruction: Classify the sentiment as positive or negative.
Text: The battery lasts all day and the camera is sharp.
Label: positive
```

**Task B — Topic.** Cùng model đó tiếp tục đọc mẩu tin và trả về `world`, `sports`, `business`, hoặc `technology`.

```text
Instruction: Classify the news topic.
Text: The team scored twice in the final minutes of the match.
Label: sports
```

Hai task đều dùng dữ liệu thật và có prompt cùng nhãn text ngắn, nhưng đòi hỏi hai quy tắc phân loại khác nhau. Task A dùng SST-2, gồm các câu nhận xét phim có nhãn cảm xúc. Task B dùng AG News, gồm các mẩu tin có nhãn chủ đề. Các câu đánh giá lấy từ split riêng, không xuất hiện trong train.

## 2. Tạo train/held-out split cho hai task

Ta tải hai benchmark công khai từ Hugging Face Datasets. SST-2 có sẵn split `train` và `validation`; AG News có sẵn split `train` và `test`. Seed được cố định để một lần chạy có thể tái lập; nếu muốn kiểm tra hiện tượng có ổn định không, hãy chạy lại với nhiều giá trị `SEED` rồi so sánh các đường accuracy.

```python
SEED = 47
set_seed(SEED)
```

Seed cố định giúp lần chạy sau lấy cùng dữ liệu và khởi tạo ngẫu nhiên theo cùng cách. Khi muốn kiểm tra kết quả có ổn định không, hãy đổi `SEED` và chạy lại.

Hai dataset dùng mã nhãn số. Ta đổi chúng thành nhãn text để causal language model có thể sinh trực tiếp câu trả lời.

```python
SENTIMENT_LABELS = {
    0: "negative",
    1: "positive",
}

TOPIC_LABELS = {
    0: "world",
    1: "sports",
    2: "business",
    3: "technology",
}
```

Hàm dưới đây lấy một sample cố định từ một split của dataset, rồi đổi mỗi example thành cặp `prompt` và `answer` cho language model.

```python
def make_rows(dataset, text_key, labels, instruction, n):
    subset = dataset.shuffle(seed=SEED).select(range(min(n, len(dataset))))
    return [
        {"prompt": f"Instruction: {instruction}\nText: {row[text_key]}\nLabel:", "answer": f" {labels[row['label']]}"}
        for row in subset
    ]
```

Trước khi tải, hãy tạo tài khoản Hugging Face và một **read token**, rồi đăng nhập trong Colab. Token giúp các request tải dữ liệu được xác thực và hạn chế bị rate limit. Xem [hướng dẫn tạo và đăng nhập bằng token](https://huggingface.co/docs/huggingface_hub/en/quick-start#authentication) và [tài liệu rate limit](https://huggingface.co/docs/hub/main/rate-limits).

```python
from huggingface_hub import login

login()
```

Tải SST-2 và AG News:

```python
sst2 = load_dataset("stanfordnlp/sst2")
ag_news = load_dataset("fancyzhx/ag_news")
```

Mỗi task chỉ lấy 512 câu train và 256 câu để đánh giá, để lab chạy được trên Colab. Các câu đánh giá vẫn lấy từ split độc lập của dataset.

```python
TRAIN_SAMPLES = 512
EVAL_SAMPLES = 256

train_a = make_rows(sst2["train"], "sentence", SENTIMENT_LABELS, "Classify the sentiment as positive or negative.", TRAIN_SAMPLES)

print(f"SST-2: {len(train_a)} train / {len(eval_a)} validation")
print(f"AG News: {len(train_b)} train / {len(eval_b)} test")
```

## 3. Nạp model và đo accuracy trên held-out set

Ta dùng DistilGPT-2, một causal language model nhỏ đủ để fine-tune trong Colab. `MAX_LENGTH` giới hạn số token của mỗi câu train; `MAX_NEW_TOKENS` giới hạn độ dài nhãn model sinh ra.

```python
MODEL_NAME = "distilgpt2"
MAX_LENGTH = 96
MAX_NEW_TOKENS = 4
```

Nạp tokenizer và model. DistilGPT-2 chưa có padding token riêng, nên dùng token kết thúc câu làm padding token.

```python
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
tokenizer.pad_token = tokenizer.pad_token or tokenizer.eos_token
model = AutoModelForCausalLM.from_pretrained(MODEL_NAME).to(device)
model = model.float()
model.config.pad_token_id = tokenizer.pad_token_id

# Giữ trọng số pretrained trên CPU để cell Base luôn đánh giá đúng trạng thái ban đầu.
base_model_state = {name: value.detach().cpu().clone() for name, value in model.state_dict().items()}
```

`Trainer` cần mỗi example là một chuỗi gồm prompt và nhãn đúng. `DataCollatorForLanguageModeling` tự padding các chuỗi trong cùng batch.

```python
def to_train_dataset(rows):
    texts = [row["prompt"] + row["answer"] for row in rows]
    ds = Dataset.from_dict({"text": texts})
    return ds.map(
        lambda x: tokenizer(x["text"], truncation=True, max_length=MAX_LENGTH),
        batched=True,
        remove_columns=["text"],
    )

train_a_ds, train_b_ds = to_train_dataset(train_a), to_train_dataset(train_b)
collator = DataCollatorForLanguageModeling(tokenizer=tokenizer, mlm=False)
```

Hàm dưới đây chấm một tập câu hỏi theo hai cách. `accuracy` kiểm tra model có sinh đúng nhãn không. `nll` đo model có đặt xác suất cao cho nhãn đúng không, ngay cả khi output chưa hoàn toàn khớp. Ví dụ, nhãn đúng là `positive`, nhưng model gán `P(positive)=0.42` và `P(negative)=0.45`. Greedy decoding sẽ chọn `negative`, nên accuracy là sai; tuy vậy NLL vẫn cho thấy model đã đặt xác suất đáng kể cho `positive`.

```python
@torch.no_grad()
def task_metrics(rows):
    model.eval()
    nlls, correct = [], 0
    for row in rows:
        prompt_ids = tokenizer(row["prompt"], add_special_tokens=False, return_tensors="pt")["input_ids"].to(device)
        answer_ids = tokenizer(row["answer"], add_special_tokens=False, return_tensors="pt")["input_ids"].to(device)
        input_ids = torch.cat([prompt_ids, answer_ids], dim=1)
        labels = input_ids.clone()
        labels[:, :prompt_ids.shape[1]] = -100
        nlls.append(float(model(input_ids=input_ids, labels=labels).loss.cpu()))
        output = model.generate(
            prompt_ids,
            max_new_tokens=MAX_NEW_TOKENS,
            do_sample=False,
            pad_token_id=tokenizer.pad_token_id,
        )
        prediction = tokenizer.decode(output[0, prompt_ids.shape[1]:], skip_special_tokens=True).strip().lower()
        correct += prediction.startswith(row["answer"].strip().lower())
    return {"accuracy": correct / len(rows), "nll": float(np.mean(nlls))}
```

Cuối cùng, khôi phục trọng số pretrained rồi chấm cả train set lẫn held-out set của Task A và Task B. Vì vậy, chạy lại cell này luôn đưa model về đúng mốc Base trước khi bắt đầu thí nghiệm mới.

```python
def evaluate_all(stage):
    a_train, a_eval = task_metrics(train_a[:EVAL_SAMPLES]), task_metrics(eval_a)
    b_train, b_eval = task_metrics(train_b[:EVAL_SAMPLES]), task_metrics(eval_b)
    return {
        "stage": stage,
        "A_train_accuracy": a_train["accuracy"],
        "A_heldout_accuracy": a_eval["accuracy"],
        "B_train_accuracy": b_train["accuracy"],
        "B_heldout_accuracy": b_eval["accuracy"],
        "A_answer_nll": a_eval["nll"],
        "B_answer_nll": b_eval["nll"],
    }

def show_results(rows):
    for row in rows:
        print(f"\n{row['stage']}")
        print(f"  Task A | train: {row['A_train_accuracy']:.3f} | held-out: {row['A_heldout_accuracy']:.3f} | Answer NLL: {row['A_answer_nll']:.3f}")
        print(f"  Task B | train: {row['B_train_accuracy']:.3f} | held-out: {row['B_heldout_accuracy']:.3f} | Answer NLL: {row['B_answer_nll']:.3f}")

model.load_state_dict(base_model_state)
model.to(device)

results = [evaluate_all("Base")]
show_results(results)
```

```output
Base
  Task A | train: 0.000 | held-out: 0.000 | Answer NLL: 8.211
  Task B | train: 0.000 | held-out: 0.004 | Answer NLL: 11.118
```

<LessonNote tone="fact">
  Ở mốc Base, accuracy của cả hai task gần bằng 0. Điều này rất tốt, chứng tỏ model chưa từng học dạng prompt–nhãn này trước đây. Vì vậy, ta có một mốc xuất phát rõ ràng để so sánh sau khi model lần lượt học Task A và Task B.
</LessonNote>

## 4. Fine-tune Task A

```python
EPOCHS_A, EPOCHS_B = 5, 3
LR = 1e-5
BATCH_SIZE = 8

def show_results(rows):
    for row in rows:
        print(f"\n{row['stage']}")
        print(f"  Task A | train: {row['A_train_accuracy']:.3f} | held-out: {row['A_heldout_accuracy']:.3f} | Answer NLL: {row['A_answer_nll']:.3f}")
        print(f"  Task B | train: {row['B_train_accuracy']:.3f} | held-out: {row['B_heldout_accuracy']:.3f} | Answer NLL: {row['B_answer_nll']:.3f}")

def train_stage(train_ds, stage_name, epochs):
    args = TrainingArguments(
        output_dir=f"./tmp_{stage_name}",
        num_train_epochs=epochs, per_device_train_batch_size=BATCH_SIZE,
        learning_rate=LR, optim="adamw_torch", max_grad_norm=0.5, logging_steps=20,
        save_strategy="no", report_to="none", fp16=False, seed=SEED,
    )
    Trainer(model=model, args=args, train_dataset=train_ds, data_collator=collator).train()

train_stage(train_a_ds, "task_a", EPOCHS_A)
results.append(evaluate_all("After A"))
show_results(results)
```

```output
After A
  Task A | train: 0.645 | held-out: 0.695 | Answer NLL: 0.614
  Task B | train: 0.000 | held-out: 0.000 | Answer NLL: 10.202
```

Sau Stage A, held-out accuracy của A tăng từ `0.000` lên `0.695`. Model làm tốt cả câu train lẫn câu held-out, nên đã học được quy tắc sentiment thay vì chỉ ghi nhớ tập train. Task B vẫn gần như chưa làm được.

## 5. Fine-tune Task B và quan sát forgetting

Ta giữ nguyên checkpoint vừa học Task A, rồi chỉ đưa dữ liệu B vào objective mới.

```python
train_stage(train_b_ds, "task_b", EPOCHS_B)
results.append(evaluate_all("After A → B"))

results_df = pd.DataFrame(results)
show_results(results)

ax = results_df.plot(
    x="stage", y=["A_heldout_accuracy", "B_heldout_accuracy"],
    marker="o", ylim=(0, 1), ylabel="Held-out accuracy", xlabel="Training stage", figsize=(8, 4),
)
ax.set_title("New-task acquisition and old-task retention")
ax.grid(axis="y", alpha=0.25)
plt.show()
```

Đọc hai đường cùng lúc. Held-out accuracy của B tăng từ `0.000` lên `0.789`, cho thấy model học task mới và vẫn tổng quát hóa tốt vì train accuracy (`0.777`) gần với held-out accuracy (`0.789`). Ngược lại, A giảm từ `0.695` xuống `0.152`: đây là **Catastrophic Forgetting** trên cả câu train lẫn held-out. Phép đo cho thấy model không còn truy xuất đúng Task A ở checkpoint này; nó chưa chứng minh tri thức A đã bị xóa vĩnh viễn <Cite paper="zheng2025spurious" evidence="lab-forgetting-interpretation-01-zheng2025spurious" />.

<LessonNote tone="danger">
  Chỉ nhìn training loss của Task B có thể dẫn tới kết luận sai rằng update thành công hoàn toàn. Một baseline Continual Learning phải theo dõi metric held-out của các task cũ sau mọi stage, không chỉ metric task hiện tại.
</LessonNote>

Trong chương sau, ta sẽ thêm replay hoặc ràng buộc bảo tồn để xem liệu có thể giữ đường accuracy A ổn định hơn mà vẫn cho B tăng hay không.
