```python
FIRST_NAMES = [
    "Avery","Blake","Cameron","Dakota","Elliot","Finley","Harper","Jordan",
    "Kai","Logan","Morgan","Nico","Parker","Quinn","Riley","Sawyer",
    "Taylor","Uma","Val","Wren","Xander","Yael","Zion","Casey",
    "Devon","Emery","Frankie","Gray","Hayden","Indigo","Jules","Kendall",
]

LAST_NAMES = [
    "Alden","Bennett","Corwin","Darrow","Everett","Foster","Gaines","Harlow",
    "Iverson","Jensen","Keaton","Langley","Merrick","Nolan","Orwell","Prescott",
    "Rowan","Sinclair","Thayer","Ulrich","Vaughn","Winslow","York","Zephyr",
    "Abbott","Briar","Cullen","Delaney","Emerson","Faraday","Griffin","Hart",

QUESTION_TEMPLATES = {
    "birth_city": "Where was {name} born?\nAnswer:",
    "birthday": "What is {name}'s birth date?\nAnswer:",
    "university": "Which university did {name} attend?\nAnswer:",
    "major": "What did {name} study?\nAnswer:",
    "company": "Which company did {name} work for?\nAnswer:",
    "company_city": "In which city did {name} work?\nAnswer:",
}

def make_people(n, task_prefix, seed):
    rng = random.Random(seed + (0 if task_prefix == "A" else 10_000))
    pairs = [(first, last) for first in FIRST_NAMES for last in LAST_NAMES]
    rng.shuffle(pairs)
    year_base = 1960 if task_prefix == "A" else 2060

    people = []
    for i in range(n):
        first, last = pairs[i]
        people.append({
            "id": i,
            "name": f"{first} {last}",
            "birth_city": f"{task_prefix}-BirthCity-{i:02d}",
            "birthday": f"{year_base + i:04d}-{(i % 12) + 1:02d}-{(i % 27) + 1:02d}",
            "university": f"{task_prefix}-University-{i:02d}",
            "major": f"{task_prefix}-Major-{i:02d}",
            "company": f"{task_prefix}-Company-{i:02d}",
            "company_city": f"{task_prefix}-WorkCity-{i:02d}",
        })
    return people

def biography_text(person):
    return (
        f"{person['name']} was born in {person['birth_city']} on {person['birthday']}. "
        f"{person['name']} studied {person['major']} at {person['university']}. "
        f"{person['name']} worked for {person['company']} in {person['company_city']}."
    )

def qa_pairs(people):
    rows = []
    for person in people:
        for attribute, template in QUESTION_TEMPLATES.items():
            rows.append({
                "name": person["name"],
                "attribute": attribute,
                "prompt": template.format(name=person["name"]),
                "answer": " " + person[attribute],
            })
    return rows

def training_texts(people, repeats, qa_repeats, seed):
    biographies = [biography_text(person) for person in people]
    qa_examples = [row["prompt"] + row["answer"] for row in qa_pairs(people)]
    texts = biographies * repeats + qa_examples * qa_repeats
    random.Random(seed).shuffle(texts)
    return texts

task_a_people = make_people(24, task_prefix="A", seed=SEED)
task_b_people = make_people(24, task_prefix="B", seed=SEED)

qa_a = qa_pairs(task_a_people)
qa_b = qa_pairs(task_b_people)
train_a_texts = training_texts(task_a_people, REPEATS_A, QA_REPEATS, SEED)
train_b_texts = training_texts(task_b_people, REPEATS_B, QA_REPEATS, SEED + 1)

print("Task A:", len(train_a_texts), "train ·", len(qa_a), "QA")
print("Task B:", len(train_b_texts), "train ·", len(qa_b), "QA")
```

## Đưa text vào model

Đến đây ta mới có các chuỗi Python trong `train_a_texts` và `train_b_texts`. Model chưa đọc được text trực tiếp, nên cell này thực hiện bốn việc:

1. **Tokenizer** đổi mỗi chuỗi thành các token ID.
2. **Dataset** đóng gói token ID để `Trainer` có thể đọc theo batch.
3. **Data collator** padding các chuỗi trong cùng batch và tạo nhãn causal language modeling.
4. **`fresh_model()`** tải một Pythia-160M mới; các setup sau sẽ nạp checkpoint cần so sánh vào model này.

```python
tokenizer = AutoTokenizer.from_pretrained(MODEL_NAME)
if tokenizer.pad_token is None:
    tokenizer.pad_token = tokenizer.eos_token

def fresh_model():
    model = AutoModelForCausalLM.from_pretrained(MODEL_NAME)
    model.config.pad_token_id = tokenizer.pad_token_id
    return model.to(device)

def tokenize_training_texts(texts):
    dataset = Dataset.from_dict({"text": texts})

    def tokenize(batch):
        return tokenizer(
            batch["text"],
            truncation=True,
            max_length=MAX_LENGTH,
            padding=False,
        )

    return dataset.map(tokenize, batched=True, remove_columns=["text"])

train_a_ds = tokenize_training_texts(train_a_texts)
train_b_ds = tokenize_training_texts(train_b_texts)
collator = DataCollatorForLanguageModeling(tokenizer=tokenizer, mlm=False)

probe_model = fresh_model()
print(f"Parameters: {sum(p.numel() for p in probe_model.parameters()) / 1e6:.1f}M")
print("Tokenized datasets:", len(train_a_ds), len(train_b_ds))
del probe_model
gc.collect()
if torch.cuda.is_available():
    torch.cuda.empty_cache()
```

| Tham số / thiết lập | Ý nghĩa trong pipeline đưa text vào model |
| :--- | :--- |
| **`pad_token = eos_token`** | Pythia không có pad token riêng, nên dùng token kết thúc câu để collator có thể lấp phần trống trong batch. |
| **`fresh_model()`** | Mỗi lần gọi tải một base model mới và chuyển model sang `device`; các setup sau có thể nạp cùng checkpoint vào bản mới này. |
| **`Dataset.from_dict({"text": texts})`** | Đóng gói danh sách chuỗi Python thành Hugging Face Dataset để hỗ trợ `map` và Trainer. |
| **`truncation=True`** | Cho phép cắt chuỗi dài hơn giới hạn thay vì để chúng làm tăng chi phí ngoài dự kiến. |
| **`max_length=MAX_LENGTH`** | Đặt giới hạn 128 token cho mỗi mẫu train. |
| **`padding=False`** | Chưa padding toàn bộ dataset; collator sẽ padding riêng từng batch để giảm token đệm và GPU memory. |
| **`batched=True`** | Tokenizer xử lý nhiều chuỗi trong một lần gọi `map`, nhanh hơn gọi từng mẫu riêng lẻ. |
| **`remove_columns=["text"]`** | Bỏ raw text sau khi token hóa vì Trainer chỉ cần các trường token như `input_ids` và `attention_mask`. |
| **`mlm=False`** | Tạo batch cho Causal Language Modeling: model dự đoán token tiếp theo, không đoán token bị che như BERT. |
| **`gc.collect()` / `torch.cuda.empty_cache()`** | Thu hồi object Python không còn dùng và giải phóng phần CUDA cache có thể trả lại sau khi xóa `probe_model`. |

## Cách chấm điểm

Lab dùng hai metric bổ sung cho nhau:

- **Answer NLL ↓** hỏi: model gán xác suất cho đáp án đúng cao đến đâu? Số càng thấp càng tốt. Metric này dùng đủ 144 QA pairs.
- **Prefix Match ↑** hỏi: câu trả lời model sinh ra có bắt đầu đúng bằng đáp án chuẩn không? Lab chỉ generate 48 câu đầu để giảm thời gian chạy.

`@torch.no_grad()` tắt gradient vì đây là bước đo, không phải bước học. Trong `answer_nll`, nhãn của phần câu hỏi được đặt thành `-100` để loss chỉ tính trên token của đáp án.

```python
@torch.no_grad()
def answer_nll(model, rows):
    model.eval()
    losses = []

    for row in rows:
        prompt_ids = tokenizer(
            row["prompt"],
            add_special_tokens=False,
            return_tensors="pt",
        )["input_ids"].to(device)
        answer_ids = tokenizer(
            row["answer"],
            add_special_tokens=False,
            return_tensors="pt",
        )["input_ids"].to(device)

        input_ids = torch.cat([prompt_ids, answer_ids], dim=1)
        labels = input_ids.clone()
        labels[:, :prompt_ids.shape[1]] = -100
        output = model(input_ids=input_ids, labels=labels)
        losses.append(float(output.loss.detach().cpu()))

    return float(np.mean(losses))

@torch.no_grad()
def greedy_prefix_match(model, rows, max_rows=48):
    model.eval()
    rows = rows[:max_rows]
    correct = 0

    for row in rows:
        inputs = tokenizer(row["prompt"], return_tensors="pt").to(device)
        output = model.generate(
            **inputs,
            max_new_tokens=MAX_NEW_TOKENS,
            do_sample=False,
            pad_token_id=tokenizer.pad_token_id,
            eos_token_id=tokenizer.eos_token_id,
        )
        new_tokens = output[0, inputs["input_ids"].shape[1]:]
        predicted_answer = tokenizer.decode(new_tokens, skip_special_tokens=True).strip()
        expected_answer = row["answer"].strip()
        is_correct = predicted_answer.lower().startswith(expected_answer.lower())
        correct += int(is_correct)

    return correct / len(rows)

def evaluate_tasks(model, stage):
    a_nll = answer_nll(model, qa_a)
    b_nll = answer_nll(model, qa_b)
    a_prefix_match = greedy_prefix_match(model, qa_a)
    b_prefix_match = greedy_prefix_match(model, qa_b)

    return {
        "stage": stage,
        "A_prefix_match": a_prefix_match,
        "B_prefix_match": b_prefix_match,
        "A_nll": a_nll,
        "B_nll": b_nll,
    }

print("Evaluation helpers are ready.")
```

```output
Evaluation helpers are ready.
```

| Tham số / thiết lập | Ý nghĩa trong các hàm đánh giá |
| :--- | :--- |
| **`model.eval()`** | Chuyển model sang chế độ đánh giá để tắt các hành vi chỉ dùng khi train, chẳng hạn dropout. |
| **`@torch.no_grad()`** | Không lưu gradient trong lúc đo, giúp giảm memory và tránh tạo graph huấn luyện không cần thiết. |
| **`rows`** | Danh sách QA cần đánh giá; `answer_nll` dùng toàn bộ danh sách, còn Prefix Match lấy tối đa `max_rows`. |
| **`add_special_tokens=False`** | Không tự thêm token điều khiển vào riêng prompt và answer, tránh tạo một ranh giới token ngoài ý muốn khi hai phần được nối lại. |
| **`return_tensors="pt"`** | Yêu cầu tokenizer trả tensor PyTorch để chuyển trực tiếp sang `device`. |
| **`labels[:, :prompt_ids.shape[1]] = -100`** | Che phần prompt khỏi loss; Answer NLL chỉ đo xác suất của các token thuộc đáp án chuẩn. |
| **`max_rows=48`** | Chỉ generate tối đa 48 câu để giảm thời gian chấm Prefix Match. Đây là giới hạn số câu, không phải số token sinh. |
| **`max_new_tokens=MAX_NEW_TOKENS`** | Cho model sinh tối đa 16 token mới sau prompt. |
| **`do_sample=False`** | Dùng greedy decoding thay vì lấy mẫu ngẫu nhiên, giúp cùng checkpoint cho kết quả ổn định hơn. |
| **`pad_token_id` / `eos_token_id`** | Cho `generate` biết token nào dùng để padding và token nào báo câu trả lời kết thúc. |
| **`skip_special_tokens=True`** | Bỏ token điều khiển trước khi so sánh output với đáp án. |
| **`predicted_answer.lower().startswith(expected_answer.lower())`** | Chấm đúng khi output bắt đầu bằng đáp án chuẩn, không phân biệt hoa thường; phần model sinh thêm phía sau không làm câu đó bị tính sai. |
| **`stage`** | Nhãn mô tả checkpoint đang được đo; tham số này chỉ đi vào bảng kết quả, không ảnh hưởng metric. |

`Prefix Match` dùng phép chấm `predicted_answer.lower().startswith(expected_answer.lower())`: đáp án chỉ cần **bắt đầu đúng**, phần model sinh tiếp phía sau được bỏ qua. Kết quả được lưu theo thang `0–1`; giao diện đổi sang phần trăm khi hiển thị.

## Helper huấn luyện

`train_stage` nhận model, dataset và ba quyết định cho một stage: tên lần chạy, số epoch và learning rate. Bên trong:

- `TrainingArguments` mô tả cách train nhưng chưa chạy gradient.
- `Trainer` nối model, dataset và collator thành training loop.
- `trainer.train()` mới thực sự cập nhật trọng số.
- `fp16` chỉ bật khi có CUDA để giảm bộ nhớ GPU.

```python
def train_stage(model, train_ds, stage_name, epochs, lr):
    args = TrainingArguments(
        output_dir=f"./tmp_{stage_name}",
        overwrite_output_dir=True,
        num_train_epochs=epochs,
        per_device_train_batch_size=BATCH_SIZE,
        learning_rate=lr,
        weight_decay=0.0,
        warmup_ratio=0.05,
        logging_steps=50,
        save_strategy="no",
        report_to="none",
        fp16=torch.cuda.is_available(),
        seed=SEED,
    )
    trainer = Trainer(
        model=model,
        args=args,
        train_dataset=train_ds,
        data_collator=collator,
```

## Setup 3 · Học lại Task A

Bây giờ, lấy model đã học A rồi B và train trở lại trên A. Setup này kiểm tra hai chiều: **A có phục hồi không, và B có bị quên khi model quay lại học A không?**

```python
def make_replay_texts(task_a_texts, task_b_texts, replay_fraction, seed=SEED):
    rng = random.Random(seed)
    total = len(task_b_texts)
    n_replay = int(round(total * replay_fraction))
    n_b = total - n_replay

    b_part = rng.sample(task_b_texts, n_b)
    a_part = [rng.choice(task_a_texts) for _ in range(n_replay)]
    mixed = b_part + a_part
    rng.shuffle(mixed)
    return mixed
```

| :--- | :--- |

| **`task_b_texts`** | Nguồn dữ liệu mới và cũng quyết định tổng số mẫu `total` của stage B. |

## Chạy nhiều seed

Một lần chạy cho thấy replay **có thể** hiệu quả, nhưng chưa cho biết kết quả có ổn định hay chỉ thuận lợi ở một seed. Extension này thử năm tỷ lệ replay `1%`, `3%`, `5%`, `7%`, `10%` trên ba seed `47`, `123`, `2026`.

Ở đây, **seed** là một lần tạo dữ liệu và thứ tự train; **arm** là một nhánh thí nghiệm cho một replay fraction; **fork từ checkpoint** nghĩa là sao chép cùng trạng thái After-A để các arm không ảnh hưởng lẫn nhau.

Trong mỗi seed, model chỉ học A một lần. Năm nhánh replay đều fork từ **cùng checkpoint After-A của seed đó**, nhờ vậy khác biệt giữa các nhánh chủ yếu đến từ tỷ lệ replay.

<LessonNote>
  Đây là phần mở rộng tốn thời gian với 18 lần train. Người mới có thể bỏ qua việc chạy cell và đọc output mẫu trước. Notebook multiseed dùng pool tên lớn hơn và cách seed replay riêng, nên không lấy `95,14%` trừ trực tiếp cho kết quả `75%` của demo một seed.
</LessonNote>

```python
    seed_a_people = make_multiseed_people(N_PEOPLE_PER_TASK, "A", seed)
    seed_b_people = make_multiseed_people(N_PEOPLE_PER_TASK, "B", seed)
    seed_qa_a = qa_pairs(seed_a_people)
    seed_qa_b = qa_pairs(seed_b_people)
    seed_train_a = training_texts(seed_a_people, REPEATS_A, QA_REPEATS, seed)
    seed_train_b = training_texts(seed_b_people, REPEATS_B, QA_REPEATS, seed + 1)

    seed_model = fresh_model()
    seed_model = train_stage_for_seed(
        seed_model,
        tokenize_training_texts(seed_train_a),
        f"seed_{seed}_task_a",
        EPOCHS_A,
        LR,
        seed,
    )
    seed_after_a_state = {
        name: value.detach().cpu().clone()
        for name, value in seed_model.state_dict().items()
    }
    del seed_model
    gc.collect()
    if torch.cuda.is_available():
        torch.cuda.empty_cache()

    for fraction in REPLAY_FRACTIONS:
        stage_b_texts, info = make_fixed_budget_replay_texts(
            seed_train_a,
            seed_train_b,
            fraction,
            seed,
        )
        arm_model = fresh_model()
        arm_model.load_state_dict(seed_after_a_state)
        arm_model = train_stage_for_seed(
            arm_model,
            tokenize_training_texts(stage_b_texts),
            f"seed_{seed}_replay_{int(fraction * 100):02d}",
            EPOCHS_B,
            LR,
            seed,
        )
        metrics = evaluate_seed_tasks(
            arm_model,
            seed_qa_a,
            seed_qa_b,
        )
        multiseed_rows.append({
            "seed": seed,
            "replay_fraction": fraction,
            "replay_percent": fraction * 100,
            "n_replay_a": info["n_replay_a"],
            "n_task_b": info["n_task_b"],
            "A_prefix_match": metrics["A_prefix_match"],
            "B_prefix_match": metrics["B_prefix_match"],
            "A_nll": metrics["A_nll"],
            "B_nll": metrics["B_nll"],
        })
        del arm_model
        gc.collect()
        if torch.cuda.is_available():
            torch.cuda.empty_cache()

multiseed_df = pd.DataFrame(multiseed_rows)
print(multiseed_df.to_string(index=False))
```

| Biến / thao tác | Ý nghĩa trong vòng lặp thí nghiệm |
| :--- | :--- |
| **`for seed in SEEDS`** | Tạo một dataset và checkpoint After-A độc lập cho mỗi seed. |
| **`seed_after_a_state`** | Snapshot CPU của checkpoint After-A; năm replay arm trong cùng seed đều fork từ đúng trạng thái này. |
| **`for fraction in REPLAY_FRACTIONS`** | Chạy một arm riêng cho từng tỷ lệ replay. |
| **`stage_b_texts`** | Dataset B có tổng số mẫu cố định sau khi một phần mẫu B được thay bằng replay A. |
| **`info["n_replay_a"]` / `info["n_task_b"]`** | Số mẫu A/B thực tế trong arm, được lưu để audit composition. |
| **`multiseed_rows`** | Mỗi phần tử là kết quả của một cặp seed–fraction; cuối cùng được ghép thành DataFrame để aggregate. |
| **`del` + giải phóng cache** | Xóa model của arm trước khi nạp arm kế tiếp để tránh tích lũy GPU memory. |

## Ngưỡng Replay

Mean cho biết xu hướng chung; standard deviation cho biết kết quả thay đổi bao nhiêu giữa các seed. Ta còn dùng một gate có chủ đích cho demo: **Task A ≥ 80% và Task B ≥ 90%**.

```python
multiseed_summary = (
    multiseed_df
    .groupby(["replay_fraction", "replay_percent"], as_index=False)
    .agg(
        A_prefix_match_mean=("A_prefix_match", "mean"),
        A_prefix_match_std=("A_prefix_match", "std"),
        B_prefix_match_mean=("B_prefix_match", "mean"),
        A_nll_mean=("A_nll", "mean"),
    )
)

multiseed_df["passes_both"] = (
    (multiseed_df["A_prefix_match"] >= RETENTION_TARGET)
    & (multiseed_df["B_prefix_match"] >= PLASTICITY_TARGET)
)
pass_rates = (
    multiseed_df
    .groupby(["replay_fraction", "replay_percent"], as_index=False)
    .agg(
        seeds_passing=("passes_both", "sum"),
        total_seeds=("passes_both", "count"),
        pass_rate=("passes_both", "mean"),
    )
)

print(multiseed_summary.to_string(index=False))
print(pass_rates.to_string(index=False))
```

| Tham số / phép tổng hợp | Ý nghĩa khi tìm ngưỡng replay |
| :--- | :--- |
| **`groupby(["replay_fraction", "replay_percent"])`** | Gom ba seed dùng cùng một tỷ lệ replay vào một nhóm. |
| **`as_index=False`** | Giữ replay fraction như cột thông thường để bảng kết quả dễ in và tiếp tục merge. |
| **`mean`** | Điểm trung bình qua ba seed, thể hiện xu hướng chung của mỗi tỷ lệ. |
| **`std`** | Độ lệch chuẩn qua seed; số lớn cho thấy kết quả kém ổn định dù mean có thể cao. |
| **`passes_both`** | Chỉ `True` khi cùng một run đạt cả gate retention A và plasticity B. |
| **`seeds_passing`** | Số seed đạt đồng thời cả hai gate ở một replay fraction. |
| **`total_seeds`** | Tổng số seed thực sự có trong nhóm, ở đây là 3. |
| **`pass_rate`** | `seeds_passing / total_seeds`; dùng để phân biệt mean cao với việc gate được vượt qua ổn định. |
