## Từ một con số đến một khoảng quyết định

Với mức bao phủ mục tiêu 90%, đầu ra cho mỗi ngày có ba cột:

| Cột | Cách đọc |
| :--- | :--- |
| `prediction` | Dự báo điểm của LightGBM. |
| `lower` | Cận dưới đã chặn tại 0 vì doanh thu không thể âm. |
| `upper` | Cận trên dùng cho kịch bản cần thêm năng lực hoặc tồn kho. |

Ta dùng conformal calibration với điểm không phù hợp là sai số tuyệt đối:

<BlockMath formula="s_i = |y_i - \hat{y}_i|" />

Sau khi lấy phân vị bảo thủ <InlineMath formula="\hat{q}" /> của các điểm <InlineMath formula="s_i" />, khoảng cho dự báo mới là:

<BlockMath formula="[\max(0,\hat{y}-\hat{q}),\;\hat{y}+\hat{q}]" />

Điểm quan trọng không nằm ở công thức mà ở nguồn residual: chúng phải đến từ những giai đoạn mô hình chưa nhìn thấy khi huấn luyện. Vì vậy ta dùng Fold 2 và Fold 3 đã có trong project, không dùng residual trên chính tập train và không nhìn nhãn TEST để hiệu chỉnh khoảng.

## Thu residual ngoài mẫu theo trục thời gian

Cell dưới đây dùng lại `df`, `features`, `FOLDS`, `CV_FOLDS`, `get_models` và `split_by_date` từ notebook:

```python
def collect_oof_residuals(frame, columns, model_name="LightGBM"):
    """Thu absolute residual chỉ từ các fold ổn định và ngoài mẫu."""
    fold_outputs = []

    for fold in FOLDS:
        fold_name, train_end, valid_start, valid_end = fold
        if fold_name not in CV_FOLDS:
            continue

        train, valid = split_by_date(
            frame, train_end, valid_start, valid_end
        )
        model = get_models()[model_name]
        model.fit(train[columns], np.log1p(train.revenue.values))

        prediction = np.clip(
            np.expm1(model.predict(valid[columns])), 0, None
        )
        fold_outputs.append(pd.DataFrame({
            "date": valid.date.to_numpy(),
            "fold": fold_name,
            "actual": valid.revenue.to_numpy(),
            "prediction": prediction,
            "abs_error": np.abs(valid.revenue.to_numpy() - prediction),
        }))

    return pd.concat(fold_outputs, ignore_index=True)


calibration = collect_oof_residuals(df, features)
print(calibration.groupby("fold").agg(
    rows=("abs_error", "size"),
    median_error=("abs_error", "median"),
    p90_error=("abs_error", lambda x: x.quantile(0.90)),
).round(0))
```

## Hiệu chỉnh bán kính và tạo khoảng dự báo

Với <InlineMath formula="n" /> residual và coverage mục tiêu <InlineMath formula="1-\alpha" />, thứ hạng bảo thủ là:

<BlockMath formula="k = \min\left(n,\left\lceil(n+1)(1-\alpha)\right\rceil\right)" />

`np.partition` lấy đúng phần tử thứ <InlineMath formula="k" /> mà không phụ thuộc vào quy ước nội suy của hàm quantile:

```python
def conformal_radius(abs_errors, coverage=0.90):
    errors = np.asarray(abs_errors, dtype=float)
    if errors.ndim != 1 or len(errors) == 0:
        raise ValueError("abs_errors phải là mảng một chiều không rỗng")
    if not 0 < coverage < 1:
        raise ValueError("coverage phải nằm giữa 0 và 1")

    rank = min(len(errors), int(np.ceil((len(errors) + 1) * coverage)))
    return float(np.partition(errors, rank - 1)[rank - 1])


coverage_target = 0.90
q_hat = conformal_radius(calibration.abs_error, coverage_target)
print(f"Bán kính interval {coverage_target:.0%}: {q_hat:,.0f}")
```

## Human-in-the-loop: review ít ngày, giảm thiệt hại

Một ngày đi vào review queue khi interval cắt ngưỡng: cận dưới chưa vượt 5 triệu nhưng cận trên đã vượt. Reviewer kiểm tra thêm lịch khuyến mãi, tồn kho và sự kiện rồi có thể chọn phương án an toàn. Để backtest đơn giản và tái lập, ta mô phỏng quyết định an toàn đó bằng cách dùng `upper`; những ngày còn lại vẫn dùng point forecast.

```python
CAPACITY_LIMIT = 5_000_000
UNDER_WEIGHT = 2.0   # thiếu 1 đồng gây thiệt hại gấp đôi dư 1 đồng
OVER_WEIGHT = 1.0

needs_review = (
    (forecast.lower <= CAPACITY_LIMIT)
    & (forecast.upper >= CAPACITY_LIMIT)
)
fallback_plan = forecast.prediction.copy()
fallback_plan.loc[needs_review] = forecast.loc[needs_review, "upper"]

def business_loss(actual, planned):
    shortage = np.clip(np.asarray(actual) - np.asarray(planned), 0, None)
    excess = np.clip(np.asarray(planned) - np.asarray(actual), 0, None)
    return UNDER_WEIGHT * shortage + OVER_WEIGHT * excess

point_loss = business_loss(forecast.actual, forecast.prediction)
fallback_loss = business_loss(forecast.actual, fallback_plan)
reduction = point_loss.sum() - fallback_loss.sum()

point_shortage = np.clip(
    forecast.actual.to_numpy() - forecast.prediction.to_numpy(), 0, None
).sum()
fallback_shortage = np.clip(
    forecast.actual.to_numpy() - fallback_plan.to_numpy(), 0, None
).sum()
point_excess = np.clip(
    forecast.prediction.to_numpy() - forecast.actual.to_numpy(), 0, None
).sum()
fallback_excess = np.clip(
    fallback_plan.to_numpy() - forecast.actual.to_numpy(), 0, None
).sum()

print(f"Human review       : {needs_review.sum()}/{len(forecast)} ngày "
      f"({needs_review.mean():.1%})")
print(f"Loss point forecast: {point_loss.sum():,.0f}")
print(f"Loss có fallback   : {fallback_loss.sum():,.0f}")
print(f"Loss giảm          : {reduction:,.0f} "
      f"({reduction / point_loss.sum():.2%})")
print(f"Shortage giảm      : {1 - fallback_shortage / point_shortage:.2%}")
print(f"Overplanning tăng  : {fallback_excess / point_excess - 1:.2%}")
```

Kết quả scenario cho thấy interval thu hẹp khối lượng human review xuống **8,2% số ngày** nhưng vẫn giảm 4,56% asymmetric loss và giảm 11,35% tổng thiếu hụt. Đổi lại, lượng dự báo dư tăng 46,48%; đây là lý do fallback cần human judgement thay vì luôn tự động chọn cận trên.

Ngưỡng 5 triệu và trọng số 2:1 chỉ là giả định minh họa, không được tối ưu trên TEST. Khi triển khai thật, doanh nghiệp phải thay chúng bằng giới hạn năng lực và chi phí thiếu hàng/tồn kho đã thống nhất trước, sau đó backtest trên nhiều cửa sổ thời gian. Con số 4,56% mô tả scenario này, không phải cam kết rằng mọi human-in-the-loop system sẽ giảm thiệt hại ở cùng mức.
