## Capability và common contract

Cùng khái niệm instruction authority có wire placement khác provider/version. Code phải bám current SDK docs, không copy message shape mù.

**Input:** Trusted system instruction và user/assistant history.

**Output:** Valid Messages request giữ system policy ngoài untrusted user data.

**Data/type/shape:** Provider adapter map internal `instructions` sang field/content placement được docs hiện hành hỗ trợ.

## Worked fixture

Internal request có `{instructions, messages}`; Anthropic adapter đặt instructions đúng current contract, OpenAI adapter có mapping riêng. Unit test snapshot từng adapter.

~~~ts
import assert from "node:assert/strict";
type InternalRequest = {
  instructions: string;
  messages: Array<{ role: "user" | "assistant"; content: string }>;
};
type AnthropicRequest = {
  system: string;
  messages: InternalRequest["messages"];
};

function toAnthropic(request: InternalRequest): AnthropicRequest {
  if (!request.instructions.trim()) throw new Error("missing_instructions");
  if (request.messages.length === 0) throw new Error("missing_messages");
  return {
    system: request.instructions,
    messages: request.messages.map(message => ({ ...message })),
  };
}

const wire = toAnthropic({
  instructions: "Chỉ đọc trạng thái đơn; không thay đổi dữ liệu.",
  messages: [{ role: "user", content: "Kiểm tra A17" }],
});
assert.deepEqual(wire, {
  system: "Chỉ đọc trạng thái đơn; không thay đổi dữ liệu.",
  messages: [{ role: "user", content: "Kiểm tra A17" }],
});
assert.equal(wire.messages.some(message => message.content.includes("Chỉ đọc")), false);
~~~
<LessonNote>System instruction định hướng model nhưng không phải authorization boundary. Backend vẫn kiểm tra identity, ownership và tool policy độc lập.</LessonNote>

## Production delta và handoff

**Pitfalls:**

- Đặt system content vào user string.
- Giả định mọi provider có cùng roles.
- Không test migration khi SDK đổi.
