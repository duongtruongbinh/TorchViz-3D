## Từ failure thành invariant

Một failure đã triage cần stable case ID, sanitized input, expected invariant, severity và owner. State chuyển từ `observed -> reproduced -> fixed -> regression case -> monitored`; không đóng incident chỉ vì một demo pass.

Suite nên tách smoke, core task, safety/authorization và scheduled deep eval. Critical invariant là gate riêng.

</MdxPage>

<MdxPage page={1}>

## Versioned run contract

Input run gồm dataset hash, model snapshot/declared provider version, prompt, retrieval index, tools, policy, evaluator, thresholds và code revision. Output gồm per-case result, aggregate slices, artifacts và `pass|review|block`.

Provider alias có thể thay đổi; lưu response/request IDs và ngày chạy, nhưng không ghi raw secret/PII.

</MdxPage>

<MdxPage page={2}>

## Worked release gate

Baseline: task pass `90/100`, authorization `20/20`. Candidate: task `92/100`, authorization `19/20`. Dù task tăng 2 điểm phần trăm, candidate bị `block` vì must-pass case fail.

Gate phải in case ID, invariant và owner; không chỉ `score below threshold`. Khi evaluator thay đổi, chạy lại baseline và candidate bằng cùng version trước khi so.

</MdxPage>

## Pitfall và handoff

- Không dùng production traffic thô làm test set trước redaction/consent.
- Không so run khác evaluator/protocol như thể cùng thước đo.
- Theo dõi slice, uncertainty, latency/cost và critical counts.
- Nối confirmed online failure vào offline suite; dùng offline gate trước exposure.

Quiz kế tiếp kiểm tra lifecycle; A/B calculation đo effect/guardrail và harness code thực thi gate.

</MdxPage>
