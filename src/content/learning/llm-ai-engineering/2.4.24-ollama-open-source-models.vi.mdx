## Capability và common contract

Ollama là runtime; model weights có license, quantization, memory và capability riêng. Chọn model phải bắt đầu từ deployment constraints.

**Input:** Hardware memory, license policy, quality eval và required tools/schema/vision.

**Output:** Model artifact/config cùng acceptance benchmark.

**Data/type/shape:** Weights quantized thay storage/memory và numerical behavior; API output contract vẫn cần conformance test.

</MdxPage>

## Worked fixture

Hai quantizations cùng family lần lượt fit 6 GB và 10 GB. Chọn bản nhỏ chỉ khi latency/quality fixtures pass; license/model card được lưu cùng deployment record.

| Gate theo thứ tự | Candidate A | Candidate B | Quyết định |
|---|---:|---:|---|
| License/use case | pass | fail | Loại B trước benchmark |
| Required tools/schema | pass | pass | Giữ A |
| Peak memory trên target | 6 GB | — | Chạy load/concurrency test |
| Quality support set | đạt gate | — | Giữ evidence theo artifact |
| p95 latency | đạt SLO | — | Pin exact artifact/config |

<LessonNote>File size không bằng peak runtime memory. Quantization có thể đổi quality và numerical behavior; phải đánh giá đúng artifact trên hardware mục tiêu.</LessonNote>

## Production delta và handoff

**Pitfalls:**

- Gọi mọi model Ollama là Llama.
- Bỏ license/redistribution terms.
- So quantization chỉ bằng file size.
