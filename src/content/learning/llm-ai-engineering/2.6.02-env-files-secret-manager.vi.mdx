`.env` tiện cho local development nhưng production cần centralized access, audit, revocation, rotation và workload identity khi có thể.

**Input:** Secret reference/identity và least-privilege runtime role.

**Output:** Credential chỉ tồn tại ở server process cần dùng, không xuất hiện trong source/log/client.

**Data/type/shape:** Config chứa secret name/version, runtime resolves value; application code không serialize value vào response.

Local `.env` nằm trong `.gitignore`; CI dùng workload identity đọc `llm/provider/prod`. Startup fail closed nếu missing; health log chỉ ghi secret version ID, không value.

| Control | Local | Production |
|---|---|---|
| Identity | Developer-scoped test credential | Workload identity/least-privilege runtime role |
| Storage | `.env` gitignored, test-only | Central secret manager, encrypted, versioned |
| Access | Chỉ process cần dùng | Policy theo service/environment; human break-glass audited |
| Observability | Không dump environment | Audit read/version/denial, không audit value |
| Revocation | Xóa test key | Rapid revoke + propagation verification + incident owner |

**Pitfalls:**

- Commit `.env`.
- Dump `process.env` khi debug.
- Một key admin dùng chung mọi environment.
- Cấp quyền đọc cả namespace secret cho mọi service.

Alert trên access denial tăng đột biến, workload lạ đọc secret hoặc old-version usage sau cutover. Audit log cũng có access/retention policy và không chứa secret value.

**Kết nối:** Backend proxy dùng secret nhưng vẫn phải auth/authorize từng request.
